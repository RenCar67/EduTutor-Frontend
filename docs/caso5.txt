 Caso semestral Instrucciones - Caso Caso EduTutor: plataforma para reserva de tutorías académicas 1. Contexto Las tutorías se coordinan por correo y la disponibilidad de los tutores vive en un Excel compartido. Se duplican horarios y nadie sabe si la sesión fue realizada. Una red de 20 centros de apoyo académico y programas de tutoría necesita una plataforma unificada para: Reservar sesiones de tutoría por la web, administrar la disponibilidad de tutores y coordinar las salas. Notificar al estudiante (email/push) y al tutor (ticket de sesión). Generar un panel de operaciones en tiempo real (sesiones por hora, tasa de asistencia, estados activos). Auditar eventos académicos (quién solicitó, confirmó, dictó o cerró una sesión). Lo que la red exige Login corporativo con Azure AD (IDaaS). Frontend Angular con MSAL y autorización por rol (Admin, Operador del dominio, Cliente del dominio). Backend Spring Boot con microservicios detrás de AWS API Gateway, protegido con el JWT de Azure AD. Despliegue en AWS EC2 con Docker / Docker Compose. Mensajería asíncrona con RabbitMQ (tareas / colas de trabajo) y streaming con Kafka (con Zookeeper) para analítica y auditoría en tiempo real. 2. Actores y roles Rol Responsabilidad Admin Administra el catálogo de asignaturas y tutores, y ve KPIs del programa. Coordinador (Operador) Confirma sesiones, asigna tutor y cierra la sesión. Estudiante (Cliente) Solicita y sigue sus sesiones de tutoría. Auditor Consulta el timeline. Solo lectura. Útil para acreditación del programa. 3. Seguridad e identidad (IDaaS Azure + API Gateway) App Registration “EduTutor”: clientId, redirectUri, authority = https://login.microsoftonline.com/&lt;TENANT_ID&gt;/ MSAL Angular: proteger rutas y adjuntar Bearer &lt;access_token&gt; a cada request. AWS API Gateway (HTTP API) con JWT Authorizer: issuer https://login.microsoftonline.com/&lt;TENANT_ID&gt;/v2.0 y audiences api://&lt;API_CLIENT_ID&gt;. Spring Security: validar el JWT con security.oauth2.resourceserver.jwt.issuer-uri y comprobar que el rol puede usar el endpoint llamado. 5. Microservicios de dominio Servicio Dominio DB Responsabilidad Exposición ms-edututor-sessions Sesiones Oracle CRUD sesiones, estados, coordinación de bloques y notificación /api/sessions/* ms-edututor-catalog Asignaturas / tutores / bloques Oracle CRUD asignaturas, tutores, bloques y cupos /api/catalog/* ms-edututor-notify Notificaciones sin DB Procesa envío email/webpush y ticket de tutor vía RabbitMQ no público (consumidor RabbitMQ) ms-edututor-audit Auditoría / timeline Oracle Consume Kafka y persiste eventos /api/audit/* (read-only) ms-edututor-report KPIs / analytics Oracle Agregaciones y endpoints de lectura (consume Kafka) /api/report/* (read-only) Debes incluir además ms-edututor-bff (Spring Boot + Spring Security) como BFF detrás del API Gateway, más un microservicio administrador de RabbitMQ y otro de Kafka, según la pauta de cada evaluación. Endpoints esenciales (ejemplos) ms-edututor-sessions POST /api/sessions (crear sesión) GET /api/sessions/{id} PUT /api/sessions/{id}/status body: { "status": "SOLICITADA|CONFIRMADA|ASIGNADA|EN_CURSO|REALIZADA|CANCELADA" } GET /api/sessions?status=...&amp;from=...&amp;to=... ms-edututor-catalog GET /api/catalog/services POST /api/catalog/services PUT /api/catalog/services/{id} (cupo/bloque) ms-edututor-report GET /api/report/kpis?range=last24h GET /api/report/top-services?range=last7d 6. Pantallas propuestas Pantalla Ruta Roles Función Login /login público MSAL. Botón «Iniciar sesión con Microsoft». Dashboard /dashboard todos los autenticados Admin: KPIs del programa. Coordinador: sesiones por confirmar y en curso. Estudiante: próximas sesiones y estado. Sesiones /sessions Admin, Coordinador, Estudiante Listar, crear (estudiante o coordinador) y cambiar estado (coordinador/admin). Catálogo académico /catalog Admin, Coordinador Asignaturas, tutores y bloques horarios. Reportería /reports Admin Sesiones por hora, tasa de asistencia, asignaturas más solicitadas. Auditoría /audit Admin, Auditor Trazabilidad de la sesión. Filtros: usuario, fechas, tipo de evento. El flujo de llamadas seguras es siempre: JWT → API Gateway → ms-edututor-bff → microservicio de dominio. 7. Despliegue (EC2 + Docker Compose) ec2-apps: sessions-svc, catalog-svc, notify-svc, report-svc, audit-svc ec2-mq: RabbitMQ (clúster de 2 nodos para las evaluaciones) con Management UI. ec2-kafka: Zookeeper (3 nodos) + Kafka (3 brokers) + Kafka UI. Un compose.yml para apps, otro para mq y otro para kafka. Security Groups: abrir solo los puertos necesarios (AMQP/5672, Kafka/9092, HTTP APIs internas). Buenas prácticas: envelope común (type, eventId, timestamp, traceId, correlationId), ACK/NACK explícitos, idempotencia y métricas de tasa de DLQ. 9.
